## 1. Роли

- **Апстрим (`microsoft/markitdown`)** — единственный источник функционального кода. Его ветки, теги и история читаются, но не правятся у нас и не удаляются у нас.
- **Дом (`rtynbirf/markitdown:main`)** — приживлённый орган: апстрим-код + мембранный слой дома (§4). Дом не переписывает апстрим-историю.

## 2. Sync-политика с апстримом

1. **Направление — только из апстрима в дом.** PR из дома в апстрим допускаются только для немембранных универсальных патчей (§4.4).
2. **Периодичность:** еженедельное обнаружение — workflow `fork-diff` (§5); исполнение синка — ручное, по свежему отчёту.
3. **Процедура синка:**
   ```bash
   git remote add upstream https://github.com/microsoft/markitdown.git
   git fetch upstream main
   git merge upstream/main        # merge, НЕ rebase дом-истории
   # конфликты — по правилу мембраны (§4.3)
   git push origin main           # только fast-forward-совместимый push; force-push запрещён
   ```
4. **Запрещено:** force-push в `main`; удаление апстрим-веток/тегов (где бы они ни появились); «разгружать» репо за счёт апстрим-сущностей; `git filter-repo` по мембранному периметру без пломбы Хозяина.
5. **Апстрим-ветки в форке** (если появятся): read-only справочник. Не мержить в `main` молча — только через cherry-pick-процедуру (§4.5) или явный merge-коммит с пояснением.

## 3. Защита веток

| Ветка | Механика | Правило |
|---|---|---|
| `main` | GitHub branch protection (API, применено 2026-11-09): `allow_force_pushes=false`, `allow_deletions=false`, `enforce_admins=false`, без обязательных статус-чеков и PR-ревью | прямой пуш волн сохранён; переписывание/удаление истории закрыто механикой, а не только словом |
| `main` | Правило роя: append-only | исключение — пломбированный мандат Хозяина |
| апстрим-ветки форка | протокол, не API | delete = нарушение протокола (это дизайн-справочник, не дефект) |

Восстановление после инцидента: удалённая апстрим-ветка восстанавливается из родителя (`git push origin upstream/<branch>:refs/heads/<branch>`), инцидент фиксируется в issue #1.

### 4.3 Правило мембраны при конфликте синка

Мембранные файлы: дом-блоки сохраняются, апстрим-изменения этих файлов переносятся вручную внутрь/вокруг дом-блоков. Немембранные файлы: берётся апстрим без правок.

### 4.4 Немембранные патчи дома

Таковых не держим: всё немембранное — апстрим как есть. Универсальное улучшение = PR в апстрим (`microsoft/markitdown`), после мержа апстримом приходит обычным синком.

### 4.5 Cherry-pick из апстрим-ветки

Если функционал непомердженной ветки апстрима нужен сейчас:
```bash
git cherry-pick <sha>            # отдельным коммитом
# сообщение: "<суть> (cherry-pick from upstream/<branch>)"
git push origin main
```
Ветка апстрима после этого не удаляется и не помечается косяком.

## 5. fork-diff (еженедельный)

Workflow `.github/workflows/fork-diff.yml`: cron раз в неделю + ручной запуск. Сверяет `main` форка против `upstream/main` (head SHA, отставание, диффстаты `llms.txt` / `README.md` / `AGENTS.md`, дом-коммиты) и публикует отчёт комментарием в issue #1 (журнал форк-протокола).

**Приёмка (машинная):** workflow зелёный на актуальном `main`; свежий отчёт-комментарий в issue #1.
